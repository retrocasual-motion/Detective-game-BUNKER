## 1. Срочно: CI и минуты GitHub (R4)

- **R4-02 · высокая.** Репозиторий приватный, тариф Free — 2000 минут Actions в месяц; по подсчёту R4
  с 1.11 ушло ~1851 минута (по отчёту; остаток видно в Settings → Billing). Съедают: e2e ~29 мин
  (до CI-B), повтор 14 упавших тестов (`retries: 1`), нет отмены старого прогона при новом пуше,
  правка только документации запускает весь e2e, push в main повторяет уже прошедшее на PR.
  Когда минуты кончатся — CI остановится до 1 декабря (или пойдёт оплата).
  Минимум: `concurrency` с отменой, `paths-ignore` для `game/docs/**` и `*.md`, e2e только на PR.
- **R4-07 · средняя.** Отчёты Playwright хранятся 90 дней: ~1,5 ГБ при 500 МБ на Free.
  Минимум: `retention-days: 7` и удалить старые.
- **R4-04 · средняя.** Красный CI стал нормой: 19 часов не собирался Docker — никто не заметил
  (это и моя ошибка 17.11). Минимум: правило в `game/CLAUDE.md` — перед «мержим?» смотреть
  `gh pr checks`, красное — не мержить без объяснения.

## 3. Сохранение: где можно потерять работу

- **R2-02 · высокая.** Две вкладки или два устройства: побеждает записавший последним. Фоновая
  вкладка сама пишет старое состояние, когда приходит письмо. `seq` берётся из часов компьютера:
  если часы спешат, сохранения с другого устройства молча отбрасываются, а клиент пишет «сохранено».
  Минимум: одна активная вкладка (`BroadcastChannel`). Полнее: версию назначает сервер, при
  расхождении — 409.
- **R2-03 · средняя.** Ответы 401/400 повторяются бесконечно, игрок видит только «Не сохранено».
  Одна устаревшая ссылка в состоянии (после «Нового дела» в соседней вкладке) блокирует все
  сохранения (`invalidReference`, проверено). Нет предупреждения при закрытии вкладки с несохранённым.
- **R2-04 · средняя.** «Новое дело» и «Выйти» не останавливают сохранение: при сбое старое
  состояние может вернуться в новое дело.
- **R2-05 · средняя.** «Решить дело»: сбой сети — кнопка молча снова доступна; если состояние
  заключения не загрузилось, игрок с отправленным заключением видит «Решить дело».
- **R2-06 · низкая.** Ноутбук не дописывает сохранение окон, если отойти в первые 0,4 с (ПК — дописывает).

## 5. Правила дела, которые сервер считает не так

- **R1-05 · средняя.** Письмо, отправленное на «Входящих на столе», после переключения на настоящую
  почту до срока доставки не приходит никогда; клиент ждёт его вечно. (скрипт R1)
- **R1-06 · средняя.** Любое действие через 2 минуты стирает счётчик отказов запросов в бюро,
  рассчитанный на 10 минут: лимит запросов зависит от того, трогал ли игрок что-то ещё. (скрипт R1)
- **R1-09 · низкая.** Лимит попыток обходится: цель под два правила считается по первому; «Новое
  дело» стирает счётчики — PIN телефона перебирается скриптом; так же — ответы заключения.
  Вредит только читеру. **Решить автору**, принимать ли это как цену «Нового дела».
- **R2-11 · низкая.** В коде страницы видно, что лист 51 и обрывок 42/1 — один лист (L990).
  Текста L990 нет. Не обязательно чинить.

## 6. Скорость и память (после CI-B)
