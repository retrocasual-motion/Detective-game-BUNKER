# Пакет игрока: формат и правила сборки

Пакет игрока — то, что игрок видит в игре на текущей итерации, и ничего больше.
Своды 01–04 для этого не годятся: они авторские, в них ответ и интерпретации
(даже 03 «что знает игрок» смешивает видимое с авторскими пояснениями). Пакет
собирается **отдельной задачей** (detective-architect, состав выбирает автор),
проверяется detective-auditor в режиме F и утверждается автором.

Пока игровые материалы не изготовлены, пакет — **бумажный прототип** (TEST-03:
«тестировать краткие обозначения сведений и вопросов»): каждый материал описан
так, как его воспринимает игрок, без пояснений, зачем он нужен.

## Структура

```
playtest/packs/<версия>/
  PACK.md                — паспорт пакета
  player/                — выдаётся игроку на старте
    00_ВВОДНАЯ.md        — роль игрока, задача, интерфейс и его действия
    <NN>__<название>.md  — один материал = один файл
  locked/                — открывается действием игрока
    L<NN>__<название>.md
  gm/                    — только для ведущего, игроку не копируется
    access.json          — правила доступа
    forbidden-terms.txt  — (необязательно) слова и regex, которых не должно быть в материалах
    lint-allow.txt       — (необязательно) исключения для lint (например, внутриигровой код вида A05)
    sources.md           — откуда взят каждый материал (ID сводов) — для автора и аудитора
```

`PACK.md`:
```
version: v3-2026-11-XX
built-from: своды v3 по A-…; список ID — gm/sources.md
built-by: …
approved-by-author: yes        ← ставит только автор
date: …
```

## Правила описания материалов

1. **Только поверхность.** Что буквально написано, видно или слышно. Никаких
   «это важно», «обратите внимание», «по-видимому», выводов R и сведений F как
   формулировок.
2. **Голос мира.** Текст материала — голос его автора внутри мира (протокол,
   журнал, письмо). Слова «улика», «игрок», «ложный след», авторские ID — нельзя.
3. **Нетекстовые носители** в бумажном прототипе:
   - фото — перечень всего, что в кадре, **с равным весом**; важная деталь не
     первая, не подробнее остальных; есть обычные детали;
   - аудио — расшифровка с таймкодами и звуковыми событиями `[шаги, 00:41–00:44]`,
     без опознания голосов, если в записи их не называют;
   - видео — раскадровка по таймкодам: кто/что видно в кадре, движение, без
     пояснения смысла;
   - план — описание или изображение в `player/` (если это картинка, lint её не
     проверит — смотри вручную);
   - предмет — что видно с каждого ракурса, маркировки.
   Выделенность — главная утечка бумажного прототипа: если нужную деталь
   описать лучше прочих, это подсказка, которой в игре не будет.
4. **Полнота стадии.** Всё, что игрок в игре видит на старте, есть в `player/`;
   материалы, которых в игре нет, не добавляются ради теста.
5. **Имена файлов** нейтральны: номер и название, как в интерфейсе игры. Не
   выдают важности, роли и порядка решения.
6. **Поиск внутри материалов** (если в игре есть поиск) описывается правилами
   `ПОИСК` в `access.json`; превью не показывает защищённое содержимое.

## access.json

```json
{
  "version": 1,
  "default_reply": {"ПАРОЛЬ": "…", "ЗАПРОС": "…", "ПОИСК": "…"},
  "rules": [
    {"id": "pw-…", "action": "ПАРОЛЬ", "target": "<regex по цели>",
     "target_label": "<как цель называется в игре>",
     "accept": ["<regex по значению>"], "release": ["L01"],
     "ok": "<ответ интерфейса при успехе>", "fail": "<ответ при неудаче>",
     "again": "<ответ при повторе>"},
    {"id": "req-…", "action": "ЗАПРОС", "target": "<regex>", "target_label": "…",
     "accept": ["<строгий regex>"],
     "intent": "<какой документ архив выдаёт по этому запросу, словами>",
     "required": ["<обязательное уточнение, например номер приложения>"],
     "release": ["L02"], "ok": "…", "fail": "…"}
  ]
}
```

- Цель и значение нормализуются (нижний регистр, ё→е, пробелы, кавычки).
- Срабатывает первое правило, где совпали действие, цель и значение. Если цель
  совпала, а значение нет — ответ `fail` первого такого правила. Иначе —
  `default_reply`.
- `accept` отражает **принятые** условия доступа (замки, адреса писем, номера
  приложений, допустимый перебор). Синонимы допускаются, если игра будет их
  принимать (CA-03: поиск вознаграждает понятие). Не расширяй условия ради теста.
- Ответы интерфейса описывают действие, не разгадку (CA-10).
- `release` — префиксы файлов в `locked/` (`L01` → `L01__…md`).
- `intent` и `required` нужны для ЗАПРОС и ПОИСК: если строгий шаблон не совпал,
  архивариус сравнивает запрос с `intent` по смыслу и требует всех уточнений из
  `required` (пустой список — уточнения не нужны). Пиши в `intent` только, **что
  выдаётся**, без пояснений, зачем это игроку. Правило без `intent` — только шаблон.
  Для ПАРОЛЬ архивариус не используется.

## Проверка перед прогоном

1. `python3 .claude/skills/detective-playtester/scripts/playtest.py lint --pack <путь>` — ошибок 0;
   каждую позицию «на проверку» просмотреть.
2. detective-auditor, режим F: утечки, выделенность, полнота, правила доступа.
3. Автор ставит `approved-by-author: yes`.
