# Отчёт playtest и передача в разбор

Кривые уверенности считает скрипт: `playtest.py metrics --run … --suspect <имя>`
(первый раунд упоминания, >50%, >80%, ложные подозреваемые ≥30%) и
`compare` для нескольких прогонов. Остальное — по записям вручную.
Решения архивариуса (`archivist-log.md`) проверь: принятые им запросы, которые
автор не принял бы, — пробел в `intent`, а не успех игрока.

Отчёт пишет ведущая сессия, которая знает решение. Поэтому правило одно:
**метрики берутся только из записей игрока** (`player-log/journal-NN.md`,
`actions-NN.md`, `gm-log.md`) с номером раунда. Записи игрока не правятся и не
«уточняются» задним числом. Где оценка — помечай «оценка ведущего».

## Метрики (по каждому профилю)

| Метрика | Как считать по записям |
|---|---|
| Правильный подозреваемый впервые | первый раунд, где он в таблице подозреваемых с уверенностью > 0 |
| Уверенность > ~50% | первый раунд; какие материалы прочитаны к этому моменту |
| Уверенность > ~80% | то же |
| Мотив понят | раунд, где в «Мотив / средства / возможность» мотив назван верно по сути |
| Средства поняты | то же |
| Возможность понята | то же |
| Где застрял | раунды без новых фактов; повторные неудачные действия (`gm-log`); СТОП |
| Бесполезные материалы | «полезно? — нет» в «Прочитано»; материалы, ни разу не названные основанием факта |
| Пропущенные материалы | выданы (`released` + `player/`), но не прочитаны; у спидраннера — сознательно пропущенные |
| Сработавшие ложные следы | ложный по сводам подозреваемый с уверенностью ≥ 30% хотя бы в одном раунде; снят ли и чем |
| Слишком сильные | скачок уверенности ≥ 30 п.п. от одного материала; ложный след сильнее официальной версии в финале |
| Честно решаемо | ФИНАЛ верен по сути и опирается на материалы, а не на «внешнее» или мета-наблюдения |
| Слишком быстро | ФИНАЛ верен раньше, чем пройдены опоры стандарта доказательности (сравнить с 03 §7–§8) |
| Скука | «скучно» в самочувствии; длинные раунды без новых фактов |
| Перегрузка | «перегружен», потерянные нити, противоречия из-за путаницы |
| Финальный reveal | доволен ли игрок объяснением (если пакет содержит финальный ответ игры); иначе «не проверено» |
| Непредусмотренные действия | строки `gm-log` с результатом «нет правила», разумные с точки зрения игрока |
| Мета-наблюдения | что игрок заметил об устройстве архива; повлияло ли на уверенность |

Отдельно отметь, ответил ли прогон на «главный вопрос плейтеста» из 03 §9 и
очередь 04 §2 п. «Плейтест» — по каждому пункту: подтверждено / опровергнуто /
не проверено этим прогоном.

## REPORT.md (в `playtest/runs/<дата>-<версия>/`)

```
# Playtest <версия пакета> — <дата>

Что это: симулированный прогон моделью без доступа к решению (профили …,
модель …, раундов …). Не плейтест на людях.
Изоляция: probe пройден; пределы — …
Запрос автора: «…»

## Итог в пяти строках
## Метрики по профилям (таблица)
## Где игроки теряли направление (шаг игрока → материал → почему)
## Ложные следы: сработали / слишком сильные / не сработали
## Скорость: самый ранний верный финал и на чём
## Непредусмотренные действия и пробелы правил доступа
## Что не проверено этим прогоном
## Находки PT-<run>-<n> (кратко, полные — в feedback/)
```

## Передача в feedback-triage

Для каждого профиля — файл `playtest/runs/<прогон>/feedback/<профиль>.md` по
`feedback-triage/references/feedback-template.md`, с изменениями:

- `source: simulated`, `persona: <профиль>`, вместо `chapters-read` —
  `materials-read: <список>`;
- «Where» — ID материала пакета и раунд, не номер главы;
- «Canon check» — ведущий сверяет со сводами: дефект дизайна / ожидаемое
  поведение (игрок ошибся там, где задумано) / вне канона.

Затем синтез по `synthesis-template.md` в `feedback/synthesis.md`:
convergent (≥ 2 профиля), divergent, single; **правки не начинаются до конца
разбора**. «Readiness verdict» — только про симулированный раунд; не объявлять
игру готовой.

## Передача detective-auditor

Аргументом: путь к `synthesis.md` и список проблемных мест (ID материалов,
раунды). Вопрос аудитору: это дефект дизайна (какой ID, какое правило) или
особенность профиля? Режимы — по типу проблемы: A (слишком быстро), C (ложный
след сильнее), E (застрял на обязательном переходе), D (игрок нашёл
противоречие).

## Автору

Коротко: главное, что показал прогон; 3–5 находок с severity аудитора; что не
проверено; путь к REPORT.md. Без предложений исправлений, пока автор не выберет,
что чинить.
