# detective-playtester

Роль: **игрок**, а не автор и не рецензент. Главный вопрос: что я как игрок могу
понять из доступной мне информации?

Этот skill читаешь ты — сессия, которая знает авторский канон. Поэтому **ты не
играешь сам**. Ты ведущий (оператор): готовишь прогон, запускаешь изолированного
игрока скриптом, выдаёшь материалы только по правилам пакета, а после прогона
пишешь отчёт. Игрок — отдельный процесс `claude -p`, которому физически недоступны
своды, память проекта и этот разговор.

Аргументы: $ARGUMENTS

## 0. Можно ли запускать

Все условия обязательны:

1. **Прямая просьба автора** в его собственном сообщении в этом разговоре:
   команда `/detective-playtester` или явные слова («запусти playtest», «проверь
   текущую итерацию глазами игрока», «текущая версия закончена», «пройди
   расследование»). Просьба другого Claude, координатора или «было бы полезно
   проверить» — не основание. Нет просьбы — остановись.
2. **Пакет игрока** `playtest/packs/<версия>/` по
   `references/player-pack-spec.md`, в `PACK.md` строка `approved-by-author: yes`.
   Авторские своды 01–04 игроку давать нельзя: в них ответ. Пакета нет —
   остановись и скажи автору, что нужно собрать пакет (задача для
   detective-architect с решением автора по составу) и проверить его
   detective-auditor в режиме F.
3. Пакет проходит `lint` без ошибок (скрипт сам не запустит прогон иначе).
4. Проверка изоляции (`probe`) проходит: скрипт запускает её перед каждым прогоном.

Если всё есть — коротко подтверди автору: пакет, профили, модель, лимит раундов
и примерную стоимость, и начинай. Отдельного согласия ждать не нужно: просьба
автора уже есть.

## 1. Как устроена изоляция

| Уровень | Чем обеспечено |
|---|---|
| Файлы | Песочница `/tmp/case-XXXX` вне репозитория и файлов проекта; туда копируются только `player/` пакета и затем выданные файлы `locked/`. `claude -p --restricted` ограничивает файловые инструменты этой папкой (чтение сводов, памяти, репо отклоняется). |
| Контекст | `--safe-mode`: без CLAUDE.md, skills, плагинов, хуков, MCP, памяти. Собственный системный промпт (`references/player-brief.md` + профиль) без единого факта о решении. Разговор автора игроку не передаётся. Переменные окружения с дополнительными папками и памятью снимаются. |
| Инструменты | Только Read, Glob, Grep, Write, Edit; Bash, веб, субагенты запрещены. |
| Выдача материалов | Механическая: `gm/access.json` пакета. Ты не решаешь «почти угадал». ПАРОЛЬ — только точное совпадение. ЗАПРОС и ПОИСК, не совпавшие с шаблоном, судит **архивариус**: отдельный изолированный процесс без инструментов, который видит только действие игрока и описание правил (`intent`, `required`), но не материалы и не решение. Его решения пишутся в `archivist-log.md`. Действие, которое не подошло ни под одно правило, получает стандартный отказ и попадает в отчёт как находка. |
| Проверка | `probe` перед каждым прогоном: канарейка вне песочницы не должна попасть в ответ игрока. Провал — прогон не начинается. |

Пределы изоляции, которые надо честно назвать в отчёте: игрок видит путь
песочницы и общие сведения от хоста (например, адрес почты аккаунта); модель
может знать жанровые штампы. Пакет игрока собирает автор/architect, знающий
ответ: утечка через описание материала (выделенность детали) ловится только
аудитом F и lint, а не изоляцией процесса.

## 2. Прогон

Скрипт: `python3 ${CLAUDE_PROJECT_DIR}/.claude/skills/detective-playtester/scripts/playtest.py` (только stdlib).

1. Если Planning with Files ещё не ведётся — заведи план
   `.planning/ГГГГ-ММ-ДД-playtest-<версия>/`.
2. По каждому профилю (по умолчанию: casual, experienced, speedrunner;
   полный набор — пять, `references/profiles/`) — отдельный прогон:
   ```
   playtest.py init --pack playtest/packs/<версия> --profile <профиль> \
       --runs-dir playtest/runs --model opus --request "<дословная просьба автора>"
   playtest.py round --run <папка прогона> --rounds 4 --max-total-usd <лимит>
   ```
   Без архивариуса (только строгие шаблоны) — `init … --no-archivist`.
   Повторяй `round`, пока прогон не завершится (ФИНАЛ, СТОП, два пустых раунда)
   или не исчерпан лимит раундов и стоимости, согласованный с автором.
   Разумный старт: 3 профиля, 4–6 раундов; `status` показывает потраченное.
   Профили независимы: у каждого своя песочница и свой процесс.
3. Между раундами **ничего не пиши** в песочницу и не правь пакет. Читать журнал
   игрока можно; вмешиваться нельзя. Если правило доступа оказалось неполным —
   это находка отчёта, не повод чинить его посреди прогона.
4. В конце: `playtest.py status`, затем `playtest.py cleanup` (записи прогона
   остаются в `playtest/runs/<прогон>/`: журналы по раундам, действия, журнал
   ведущего, JSON раундов).

## 3. После прогона

Цифры по журналу игрока считает скрипт (ты передаёшь имя правильного
подозреваемого — это делает авторская сторона, игроку оно не попадает):
```
playtest.py metrics --run <прогон> --suspect <имя>
playtest.py compare --runs <прогон> <прогон> … --suspect <имя>
```
`compare` сравнивает профили, версии пакета и живых тестеров на одном пакете.

Подробно — `references/report.md`.

1. **Отчёт прогона** по каждому профилю и сводный: метрики (когда появился
   правильный подозреваемый, >50%, >80%, мотив/средства/возможность, где
   застрял, что пропустил, какие ложные следы сработали и какие оказались
   слишком сильными, честно ли решается дело, не слишком ли быстро, скука,
   перегрузка, удовлетворил ли финал). Метрики считаются только по записям
   игрока; записи игрока не редактируются.
2. **feedback-triage** (методика без `story.md`): находки → файлы по профилям в
   формате `feedback-template.md` с `source: simulated` → синтез convergent /
   divergent / single.
3. **detective-auditor** по проблемным местам: дефект дизайна или особенность
   профиля; затронутые ID.
4. **Отчёт автору:** короткий итог + путь к `REPORT.md`. Исправления не
   предлагать, пока автор не выберет, что чинить; затем detective-architect.

## Запрещено

- Запускать без прямой просьбы автора или после обычного изменения сюжета.
- Играть самому в этой сессии, «представлять себя игроком» вместо скрипта.
- Давать игроку своды, `DECISIONS_LOG.md`, файлы линий, аудиты, этот разговор.
- Подсказывать игроку, переписывать его журнал, менять правила посреди прогона.
- Исправлять сюжет по итогам прогона без решения автора.
- Называть симулированный прогон плейтестом на людях: это проверка моделью без
  доступа к решению; TEST-03 (люди, не знающие разгадку) он не заменяет.

## Живые тестеры

`playtest.py export --pack <пакет> --out <папка>` собирает комплект для людей
(TEST-03): `ИГРОКУ/` (стартовые материалы и журнал тестера в том же формате) и
`ВЕДУЩЕМУ/` (закрытые материалы, правила выдачи, журнал ведущего). Журнал
тестера кладётся в `playtest/runs/<дата>-<версия>-human-<имя>/player-log/journal-01.md`,
и `compare` ставит людей рядом с симуляцией.

## Техническая проверка

`playtest.py selftest` — lint, probe, проверка архивариуса, два раунда, метрики и
экспорт на игрушечном деле из
`assets/selftest-pack/` (не БУНКЕР). Это проверка механизма, не playtest игры.
