# Канон, статусы и источники (общее для detective-skills)

Общий файл для detective-orchestrator, detective-architect, detective-auditor и
detective-playtester. Здесь нет сюжета: только где он лежит и как с ним обращаться.
Если этот файл расходится со сводами или с `bunker/AGENTS.md`, прав свод.

## Где лежит канон

Канон лежит в корне репозитория: `bunker/` (своды и методология), `claude/`
(журнал решений, сессии, аудиты), `Архив/` (устаревшее). Копия в файлах проекта
(`/mnt/project-files/knowledge/`) — снимок на момент переноса, не канон: не читай
её вместо репозитория и не пиши в неё.

| Что | Файл | Для чего |
|---|---|---|
| Рабочий порядок | `bunker/AGENTS.md` | что нельзя менять без автора, формат вариантов |
| Указатель | `bunker/00_INDEX.md` | какой файл актуален, что устарело |
| История и персонажи | `bunker/01_STORY_AND_CHARACTERS.md` | хронология, карточки, правила мира (§11) |
| Улики и связи | `bunker/02_CLUES_AND_CONNECTIONS.md` | E (материалы), F (сведения), R (выводы), A (доступы), N, замки, E16 |
| Знание игрока и маршруты | `bunker/03_PLAYER_KNOWLEDGE_AND_ROUTES.md` | старт S0–S4, маршруты, уровни понимания, прогоны §9 |
| Статусы | `bunker/04_STATUS_AND_OPEN_QUESTIONS.md` | действующие решения §1, очередь §2, **отвергнутое §3–§4** |
| Журнал решений | `claude/DECISIONS_LOG.md` | A-номера с причинами; последние номера читать с конца |
| Методология | `bunker/docs/DETECTIVE_DESIGN_PRINCIPLES.md` | принципы GOV…MEDIA, DESIGN VALIDATION CHECKLIST A–L |
| Получение улик | `bunker/docs/CLUE_INTERACTION_GUIDE.md` | этапы О/Д/И, правила CA-01–CA-18, карточки M01–M24 |
| Файлы линий | `claude/*_LINE_*.md`, `claude/*_SESSION.md` | итоги по персонажам; статус каждого — в `00_INDEX.md` |
| Последний аудит | см. `00_INDEX.md` | предложения, не канон |

`Архив/` — только происхождение решений. Оттуда ничего не возвращается как
действующее без решения автора.

Порядок чтения перед существенной работой: `AGENTS.md` → нужные разделы 01–04 →
последние A-номера в `DECISIONS_LOG.md` → файл линии, о которой речь. Читай
выборочно (grep по ID и именам), своды большие.

## Приоритет источников

Текущие указания автора → явно принятые решения → своды 01–04 → файлы линий →
старые исходники. Методология (`docs/`) задаёт, как проверять; она не разрешает
менять историю.

## Статусы

**утверждено · направление принято · предложено · не выбрано · отвергнуто ·
условный пример.** Подробное описание не делает идею каноном. Рекомендация Claude
не равна решению автора. «Архитектура согласована» не значит «изготовлено» или
«проверено плейтестом». Любой новый результат detective-skills получает статус
явно, обычно «предложено».

Отвергнутое (04 §3–§4) не предлагается снова без **новой конкретной причины**.
Если причина есть (например, аудитор нашёл поломку, которой при отказе не было),
назови её и номер, которым вариант был отвергнут.

## Пространства идентификаторов

Пиши ID так, как в сводах, не придумывай параллельных:

- `E00…` семейства материалов; `F01…` сведения; `R01…` выводы; `N00…` направления;
  `A00…` функции доступа; `M01…` карточки механик; `CA-01…` правила получения.
- `A-82` (с дефисом) — решение автора из журнала; коды участников этапа A тоже пишутся
  `A-11…A-31`, различай по контексту (см. 02 §1).
- Свои варианты помечай латиницей с номером (`K-1`, `E7-A`, `P-2`) — как в AGENTS.md.
- Находки аудита: `AUD-<дата>-<n>`; находки playtest: `PT-<run>-<n>`.

## Куда писать

- Своды 01–04 и `DECISIONS_LOG.md` меняются **только после явного решения автора**,
  со следующим A-номером, затронутыми разделами и статусом в 04.
- Анализ, аудит, протокол сессии можно записывать самостоятельно, с явным статусом:
  отдельным файлом рядом со сводами (`claude/AUDIT_ГГГГ-ММ-ДД_<тема>.md`,
  `claude/<ТЕМА>_SESSION.md`).
- Процесс многоэтапной задачи (план, находки, отклонённые варианты) — в
  Planning with Files: `.planning/ГГГГ-ММ-ДД-тема/` по правилам `CLAUDE.md`.
  План хранит процесс, не канон.
- Пакеты игрока и записи playtest — `playtest/` (см. detective-playtester).
