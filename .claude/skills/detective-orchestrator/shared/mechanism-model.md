# Модель детективного механизма

Общая модель для architect (строит по ней) и auditor (ищет в ней разрывы).

## Цепочка

```
персонаж → потребность/мотив → действие → последствие → след → материал
        → что видит игрок → интерпретация игрока → позднейшее раскрытие
```

Каждое звено отвечает на свой вопрос:

| Звено | Вопрос | Где в сводах |
|---|---|---|
| Персонаж | Кто, с какими интересами и знаниями в этот момент? | 01 §9–§10 |
| Мотив | Почему именно он и именно тогда? | 01 §10, файл линии |
| Действие | Что сделал, где, когда; было ли нужное знание/доступ/ресурс? | 01 §5–§8 |
| Последствие | Что изменилось в мире? | 01 |
| След | Что физически/информационно осталось, кто и почему это зафиксировал? | 02 E, паспорт материала |
| Материал | Какой носитель, как попал в дело (никто из следствия не перемещал улики)? | 02 E, §4 размещение |
| Что видит игрок | Буквальная поверхность: что видно сразу, что — только действием | 03 §10, CA-01 О/Д/И |
| Интерпретация | Первая трактовка → с чем сопоставить → какой вывод R | 02 F, R |
| Раскрытие | Когда меняется смысл; какой вывод его подтверждает | 03 §5–§8 |

**Разрыв цепочки — это находка.** Персонаж без следа — декорация. След без
причины сохраниться — авторское удобство. Материал без интерпретации — шум.
Раскрытие без опоры в доступном материале — нарушение FAIR-01.

## Паспорт материала

автор · время создания · причина создания · сохранность · путь в дело ·
режим доступности (сразу / после нахождения / защищён — чем) ·
этапы О/Д/И (обнаружение — доступ — интерпретация, CA-01).

## Независимость опор

Опоры вывода считаются по **происхождению** (CLU-03). Одно происхождение = одна
опора, сколько бы файлов его ни повторяло. Центральный вывод держится стандартом
E16 v3 (02, 03 §7): положительные опоры трёх происхождений, альтернативы снимаются
положительно. Новая улика к центральному выводу проверяется на то, какое
происхождение она добавляет и не делает ли вывод тривиальным одним сообщением.

## Ложный след (red herring)

Ложный след в БУНКЕРЕ — это **настоящая история другого персонажа**, а не
приманка автора (SUS-01, SUS-02, правила Семыкина в DP):

1. возникает из реального поступка персонажа в его интересах;
2. правдоподобен: разумный игрок может его заподозрить;
3. существует не только ради обмана (у носителя есть своя причина);
4. имеет невиновное объяснение, которое само учит игрока чему-то верному о деле;
5. разрешается положительно, а не забывается; объяснение тайны не становится
   автоматическим алиби (SUS-03).

## Версия игрока

Игрок держит гипотезы, а не список спойлеров (HYP-01). Для каждого значимого
материала полезно знать: какую версию он поддерживает, какую ослабляет, какой
вопрос оставляет, какой поворот позже переосмысляет его (HYP-02). Ранняя верная
догадка допустима, но доказать её одной линией нельзя (HYP-03, 03 §5).
