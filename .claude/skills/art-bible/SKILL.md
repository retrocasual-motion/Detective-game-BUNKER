# art-bible

Главный вопрос: **по какому правилу любой — я, сервис генерации, художник — сделает кадр «в
одном мире» с остальными и отбракует чужой?** Арт-библия — набор ограничений, а не описание
настроения.

Основа — skill `art-bible` из Donchitos/Claude-Code-Game-Studios (MIT, `LICENSE` рядом),
переделанный под архив дела и порядок работы БУНКЕРА. Шаблон и проверки лежат в `design/`,
здесь — только порядок работы.

## Прочитай до работы

1. `design/CLAUDE.md`, `design/DECISIONS.md` (ART-…) — правила и решения.
2. `design/art-bible/TEMPLATE.md` — 17 разделов; `design/art-bible/CHECKS.md` — проверки;
   `design/ASSET_REGISTRY.md` — к чему правила применяются (все материалы и предметы по линиям).
3. `design/art-bible/ART_BIBLE.md`, если уже есть. Не читай его целиком: найди заголовки
   `## N.` и строки `[Не решено]` (Grep) — так видно, какие разделы готовы.
4. По разделу — нужное из канона: `bunker/01` (мир, люди, день 13, правила мира §11),
   каталог материалов `game/docs/TECH_PLAN.md`, `bunker/docs/DETECTIVE_DESIGN_PRINCIPLES.md`
   (для столпов), `game/docs/UX_PRINCIPLES.md` (для интерфейса),
   `design/research/art-pipeline.md` (примеры игр, принципы по медиа, «не ИИ-слоп»).

## Порядок

1. **Статус.** Покажи автору таблицу «раздел → готов / не решено». Работай только с
   незаполненными; готовые не переписывай без просьбы автора.
2. **Один раздел за раз**, по порядку 0 → 16 (столпы нужны всем остальным). Автор может
   выбрать другой раздел — тогда назови, на какие незаполненные разделы он опирается.
3. **Варианты.** 2–4 действительно разных варианта, первый — минимальный, метки латинские
   (`S1-A`, `S1-B` — номер раздела и буква). Каждый — конкретным примером, а не словами:
   как выглядит один и тот же кадр из дела (например, фото лестницы утром 13-го) при этом
   варианте; что игрок видит → что может заметить. По возможности — референс (ссылка на
   реальный снимок, кадр игры или фильма) или проба с сайта генератора, если автор её сделал.
4. **Проверки до показа.** Прогони черновик через `CHECKS.md`: сужает ли выбор, есть ли
   столп и проверка «если X — выбирай Y», не спорит ли с готовыми разделами, не красивее ли
   улика фона, нет ли лишней подсказки, не меняет ли канон. Не проходит — доработай или
   прямо скажи автору, где слабость.
5. **Решение автора.** Автор выбирает в чате. Рекомендация ≠ решение.
6. **Запись — пакетом.** Когда автор говорит «собирать»: если `ART_BIBLE.md` нет — создай
   его из `TEMPLATE.md`; замени `[Не решено]` в решённых разделах (заголовки не трогай);
   запиши решения в `design/DECISIONS.md` (ART-…: выбрано, варианты, почему); обнови таблицу
   этапов в `design/README.md`. Затем ветка → PR → «мержим?».
7. **Утверждение.** Когда все разделы заполнены — итоговая проверка по `CHECKS.md`
   (первой строкой `ГОТОВО` / `ЗАМЕЧАНИЯ` / `НЕ ГОТОВО`). Для независимого взгляда предложи
   автору отдельный вызов `detective-auditor` по разделам 4, 6, 7, 12 (подсказки, анахронизмы,
   противоречия таймлайну). После утверждения — следующий этап: skill `bunker-art` (ART-4).

## Границы

- Сюжет, улики, доступы, время событий — не здесь; вопрос к канону → `detective-orchestrator`.
- Не добавляй медиа и материалы — описывай вид существующих.
- Не переписывай столпы; если столп мешает — покажи компромисс автору.
- Без отдельной задачи не пиши готовые промпты серий и не генерируй ассеты: это этапы после
  арт-библии.
