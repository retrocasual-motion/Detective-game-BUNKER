# БУНКЕР

Детективная онлайн-игра в формате расследования дела.

## Для Claude: начни здесь

Если автор дал тебе ссылку на этот репозиторий и попросил прочитать его, прочитай
файлы в этом порядке. Этого достаточно, чтобы продолжить работу с того места, где
она остановилась.

1. **`CLAUDE.md`** — целиком. Там твоя роль (соавтор, независимый критик,
   консультант), правила работы, предпочтения автора из памяти прежнего аккаунта
   и порядок работы с GitHub (ветка → PR → «мержим?»). Выполняй эти правила, даже
   если ты не в Claude Code, а в обычном чате.
2. **`bunker/00_INDEX.md`** — карта файлов и порядок чтения.
3. **`bunker/AGENTS.md`** — что нельзя менять без решения автора.
4. **`bunker/04_STATUS_AND_OPEN_QUESTIONS.md`** — действующие решения, очередь работ,
   отвергнутое.
5. **`claude/DECISIONS_LOG.md`** — последние решения (A-номера в конце журнала) и
   последние коммиты в `main`: на чём остановились.
6. Дальше — нужные разделы сводов `bunker/01–03` по теме разговора.
7. Если работа про саму игру (интерфейс, техника, разработка) — `game/README.md` и
   `game/docs/TECH_PLAN.md`.
8. Если работа про дизайн (визуальный стиль, арт-библия, персонажи, фото, документы,
   видео, звук, 3D-план, генерация картинок) — `design/README.md` и `design/DECISIONS.md`.

Skills лежат в `.claude/skills/`. В Claude Code они подключаются сами; в обычном
чате прочитай `SKILL.md` нужного skill и следуй ему как методике. Начинать —
с `detective-orchestrator`.

### Проект в двух словах

Игрок получает архив дела: документы, фото, аудио, видео, планы, аккаунты. Осень
2009, Колорадо. Компания VAULTLINE проводит месячную программу в бункере; на самом
деле фармкомпания HEXON BIO тайно испытывает на участниках вещество X-17. Внутри
восемь человек: Адам Коул (руководитель), Эмма Пирс, Дэн Миллер, Кейт Уолш, Лея
Моро, Мика Сато, Ник Харт, Габриэль Силва; снаружи — Ричард Хейл. Утром 13-го дня
Адам погибает на служебной лестнице. Действовала Лея; Эмма — главный честный
ложный след. Игрок восстанавливает, что произошло, и называет виновного.

Состояние: своды v3, решения до A-259, пакеты игрока для плейтеста до v3.3
(`playtest/packs/`), прогоны в `playtest/runs/`. Это авторский материал со
спойлерами: игроку его не выдавать.

## Структура репозитория: три части

Репозиторий делится на **сюжет** (дело, улики, канон — то, что игрок расследует),
**игру** (как это сделать браузерной игрой) и **дизайн** (как дело выглядит и звучит).
Сюжетные папки лежат в корне, как сложилось исторически: на них ссылаются сотни
файлов, журнал решений, skills и скрипты плейтеста, поэтому они не переносятся. Всё
про разработку игры — в папке `game/`, всё про визуал и медиа — в папке `design/`.

### Часть 1. Сюжет и расследование

| Папка | Что там | Статус |
|---|---|---|
| `bunker/` | своды 00–04 (сюжет и персонажи, улики и связи, знание игрока и маршруты, статусы), `AGENTS.md` (рабочий порядок), `docs/` (методология и руководство по уликам) | **канон** |
| `claude/` | журнал решений `DECISIONS_LOG.md`, сессии по линиям персонажей, предложения (`proposals/`), аудиты | журнал — канон решений; остальное — рабочие файлы |
| `playtest/` | пакеты игрока (`packs/<версия>/`: `player/`, `locked/`, `gm/`) и прогоны (`runs/`) | пакет — текстовая модель игры, источник контента для `game/` |
| `Архив/` | устаревшие сессии и своды на 2026-10-17 | история, не канон |

### Часть 2. Создание игры

| Папка | Что там |
|---|---|
| `game/` | всё про браузерную игру; вход — `game/README.md` |
| `game/docs/` | технический план (`TECH_PLAN.md`), затем решения по технике и стеку |
| `game/packages/` | код игры (карта — `game/docs/ARCHITECTURE.md`) |
| `ИГРАТЬ.cmd` | запустить игру на своём компьютере двойным щелчком (подробно — `game/docs/DEVELOPMENT.md`, раздел 3) |

### Часть 3. Дизайн: визуал и медиа

| Папка | Что там |
|---|---|
| `design/` | вход — `design/README.md` (этапы, структура, инструменты); правила — `design/CLAUDE.md`; решения автора — `design/DECISIONS.md` (ART-…) |
| `design/art-bible/` | шаблон арт-библии и проверки; рабочая арт-библия (когда появится) |
| `design/research/` | исследование: процесс, детективные игры, принципы по медиа, генераторы и skills |
| `design/blender/` | 3D-план бункера: блокаут, камеры, точки съёмки |

Сами медиа (картинки, видео, звук, 3D) в git не кладутся — только тексты: арт-библия,
карточки ассетов, логи промптов, скрипты сцен.

### Служебное

| Папка | Что там |
|---|---|
| `.claude/` | skills и настройки Claude Code |
| `.planning/` | план текущей многоэтапной задачи (planning-with-files); закончена — переносится в `planning-archive/` |
| `planning-archive/` | планы законченных задач |
| `reports/` | отчёты о настройке инструментов (detective-skills) |

Сюжетные файлы перенесены из файлов проекта claude.ai (`knowledge/`, `reports/`)
2026-10-26 без правок содержимого. Главная копия теперь здесь.

## Плагины Claude Code

В `.claude/settings.json` подключён плагин
[planning-with-files](https://github.com/OthmanAdi/planning-with-files)
(маркетплейс `OthmanAdi/planning-with-files`). В облачных сессиях его ставит
скрипт среды `detective-game-bunker` (две команды `claude plugin …`): начинай
сессии по БУНКЕРУ на этой среде.

## Skills Claude Code

В `.claude/skills/` лежат 14 project skills, отобранных по одному из
[story-skills](https://github.com/danjdewhurst/story-skills),
[claude-skills](https://github.com/alirezarezvani/claude-skills) и
[claude-cto-team](https://github.com/alirezarezvani/claude-cto-team)
(все MIT). Источники, коммиты и локальные изменения описаны в
`.claude/skills/SOURCES.md`, правила совместного использования в `CLAUDE.md`.
`reader-panel` запускается только командой `/reader-panel`.

Для дизайна — `art-bible` (переписан по skill из
[Claude-Code-Game-Studios](https://github.com/Donchitos/Claude-Code-Game-Studios), MIT):
ведёт арт-библию по разделам с проверками; шаблон и проверки лежат в `design/art-bible/`.

Поверх них — четыре собственных skill игры: `detective-orchestrator` (входная
точка, выбор режима), `detective-architect` (разработка), `detective-auditor`
(независимая проверка) и `detective-playtester` (симулированный игрок в
изолированном процессе, только командой `/detective-playtester`). Описание — в
`CLAUDE.md` и в `SKILL.md` каждого.
