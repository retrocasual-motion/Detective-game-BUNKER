# kie.ai: пачка генераций Nano Banana Pro

`kie_batch.ps1` за один запуск: проверяет задание и цену, загружает референсы, отправляет все
промпты в kie.ai **параллельно**, ждёт, скачивает картинки в папку медиа и пишет журнал.
Пачка из 9 картинок занимает примерно столько же, сколько одна (~40–60 с на стороне kie.ai).

Картинки и журнал — только в папке медиа (ART-10); в репозитории — скрипт и задания-тексты.
Платная пачка — только после оценки цены (`-DryRun`) и согласия автора (design/CLAUDE.md).

## Ключ

Скрипт берёт `KIE_API_KEY` из окружения процесса, а если там пусто — из переменных учётной
записи Windows. Задать один раз у компьютера (ключ в чат не вставлять):

```powershell
[Environment]::SetEnvironmentVariable("KIE_API_KEY", "<ключ>", "User")
```

Скрипт ключ не выводит и никуда, кроме kie.ai, не отправляет.

## Запуск

```powershell
# только проверить задание, цену и баланс — кредиты не тратятся
.\design\tools\kie\kie_batch.ps1 -JobFile .\design\tools\kie\example_K2.json -DryRun

# запустить пачку
.\design\tools\kie\kie_batch.ps1 -JobFile .\design\tools\kie\example_K2.json
```

Параметры: `-Retries 1` — сколько раз перезапустить задачу, которую kie.ai вернул как `fail`
(брак по картинке скрипт не видит — его оценивает человек); `-TimeoutMin 10` — сколько ждать всю
пачку. Если скрипт запрещён политикой: `powershell -ExecutionPolicy Bypass -File <путь> …`.

В конце — итог по задачам (`label — состояние — taskId — кредиты`), баланс и строки
`FILE: <путь>` по каждой скачанной картинке. Код выхода 2 — не все задачи успешны.

## Файл задания (JSON, UTF-8)

```json
{
  "outDir": "E:\\Projects\\bunker-media\\references\\places",
  "resolution": "2K",
  "aspect": "16:9",
  "refs": { "K2": "E:\\Projects\\bunker-media\\references\\places\\K2_cabinet_wide_v3.png" },
  "jobs": [ { "label": "K2_cabinet_wide_kie_v2", "refs": ["K2"], "prompt": "…" } ]
}
```

- `outDir` — куда сохранять; файл получает имя `<label>.png`, существующий не перезаписывается
  (`<label>_2.png` …).
- `resolution` — `1K`, `2K`, `4K`; `aspect` — `1:1, 2:3, 3:2, 3:4, 4:3, 4:5, 5:4, 9:16, 16:9, 21:9, auto`.
  Оба можно переопределить в отдельной задаче.
- `refs` — короткое имя → локальный файл (абсолютный путь или относительно файла задания) или
  уже готовая ссылка `https://…`. В задаче — до 8 референсов, в нужном порядке.
- `label` — номер генерации (K5-1, EA-2 …): по нему названа картинка и строка журнала.

## Журнал

`<outDir>\_kie_log.jsonl` — строка на задачу: время, label, состояние, taskId, модель,
разрешение, формат, кредиты, файл, ссылка на результат, референсы (файл и ссылка), промпт,
файл задания. Этого хватает, чтобы повторить генерацию и записать происхождение ассета.

## Что знать о kie.ai (проверено 26.11.2026)

- Модель `nano-banana-pro`: 18 кредитов (~$0,09) за 1K/2K, 24 (~$0,12) за 4K; кредит ≈ $0,005.
- Создание: `POST https://api.kie.ai/api/v1/jobs/createTask`; статус:
  `GET …/jobs/recordInfo?taskId=…` (`waiting / queuing / generating / success / fail`,
  ссылки — в строке `resultJson` → `resultUrls`); баланс: `GET …/chat/credit`.
- Референсы загружаются на `https://kieai.redpandaai.co/api/file-stream-upload` (до 100 МБ).
  Ссылки на них временные; сколько живут — не проверено, поэтому скрипт берёт ссылку из кэша
  (`%LOCALAPPDATA%\bunker-kie\upload_cache.json`) не дольше 24 часов, потом загружает заново.
- Готовые картинки kie.ai хранит 14 дней — скрипт сразу скачивает их к себе.
- Ошибки kie.ai приходят с HTTP 200 и другим `code` в ответе — скрипт смотрит на `code`.
