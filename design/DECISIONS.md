# Журнал решений по дизайну (ART-…)

Решения автора о визуальном стиле, медиа, инструментах и процессе дизайна. Формат — как у
`claude/DECISIONS_LOG.md` (A-…) и `game/docs/DECISIONS.md` (T-…): что выбрано, какие были
варианты, почему. Статусы: **утверждено** / **направление принято** / **не выбрано** /
**отвергнуто**. Сюжетные решения сюда не пишутся.

Основание для решений 10.11.2026 — исследование `design/research/art-pipeline.md`.

---

## ART-1. Дизайн — отдельная часть репозитория (10.11.2026)

**Утверждено.** Всё про создание визуала и медиа — в папке `design/`, рядом с сюжетом (`bunker/`,
`claude/`, `playtest/`) и игрой (`game/`). Вход — `design/README.md`, правила — `design/CLAUDE.md`.
Skills дизайна лежат в общей `.claude/skills/` (вложенные папки skills Claude Code находит
ненадёжно), содержимое, которым они пользуются, — в `design/`.

## ART-2. Процесс: гибрид, всё по одному (10.11.2026)

**Утверждено** (вариант DS-C). Сначала исследование и стиль: арт-библия, внешность персонажей,
места. Стиль ищется вручную на сайтах генераторов. Затем эталоны, затем серии — по одному
ассету, «чтобы всё было чётко и красиво». Порядок этапов — `design/README.md`.

## ART-3. Сервис генерации через MCP — пока никакой (10.11.2026)

**Утверждено** (вариант MC-C). Автор генерирует на сайтах и выбирает сервис. Higgsfield,
Magnific и другие через MCP не подключаются, skills Higgsfield не ставятся, пока автор не выберет.
Не выбрано: MC-A Higgsfield (видео, Soul ID), MC-B Magnific (апскейл, аудио, 3D).

## ART-4. Свой skill `bunker-art` — после арт-библии (10.11.2026)

**Утверждено** (вариант SK-A). После утверждения арт-библии собрать skill с её правилами: профили
камер, шаблоны промптов по типам, карточка ассета, правила «не ИИ-слоп», стоп перед платным
запуском, лог промпта рядом с файлом (идеи из generate-nanobanana). Сторонние skills целиком не
ставятся.

## ART-5. Арт-библия по шаблону Claude-Code-Game-Studios с проверками (10.11.2026)

**Утверждено** (вариант AB-A). Шаблон и проверки skill `art-bible`
(Donchitos/Claude-Code-Game-Studios, MIT) переделаны под архив дела: `design/art-bible/TEMPLATE.md`
(15 разделов: столпы, идентичность, два мира, места, носители и камеры, цвет, персонажи,
пространство, бумага, видео, звук, интерфейс, запреты, стандарты, референсы) и
`design/art-bible/CHECKS.md`. Ведёт работу skill `.claude/skills/art-bible/`.
Отвергнуто: AB-B (шаблон как есть — половина разделов про экшен), AB-C (своя структура без проверок).

## ART-6. Пространство — через 3D-блокаут в Blender (10.11.2026)

**Направление принято.** Сначала простой 3D-план бункера (серые коробки, двери, лестница) по
плану v3, в нём — камеры и точки съёмки; рендеры нужных ракурсов становятся основой для
генерации фото и кадров наблюдения. Инструмент — Blender MCP (локально) и скрипты сцены в
`design/blender/`. Подробности и что нужно для старта — `design/blender/README.md`.

## ART-7. Видео и износ записей — Remotion (10.11.2026)

**Направление принято**, ставится на этапе видео. Remotion (видео как код на React, официальные
skills `remotion-dev/skills`): сборка записей камер наблюдения, таймкод, частота кадров,
наложения, износ записи.

## ART-8. Голоса и звук — не выбрано (10.11.2026)

**Не выбрано.** ElevenLabs интересен для русских голосов и шумов, но через API каждая генерация
платная; автор смотрит сервисы, где ElevenLabs доступен иначе, и другие варианты. Официальные
skills `elevenlabs/skills` — кандидат, если выберем ElevenLabs.

## ART-9. Сторонние инструменты — по этапам (10.11.2026)

**Направление принято** (вариант IN-A). Blender MCP — когда начнём 3D-план; Remotion — на этапе видео;
аудио — после ART-8. Не ставить всё заранее: лишние skills засоряют контекст и тянут свой стиль.

В репозитории — тексты: арт-библия, карточки ассетов, логи промптов, скрипты сцен.
