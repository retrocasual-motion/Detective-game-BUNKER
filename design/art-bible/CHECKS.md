# Проверки арт-библии

Применяются к каждому разделу **до** того, как показать его автору, и ко всей арт-библии перед
утверждением. Основа — «линза арт-директора» skill `art-bible` из
[Donchitos/Claude-Code-Game-Studios](https://github.com/Donchitos/Claude-Code-Game-Studios)
(MIT, © 2026 Donchitos), переделанная под архив дела.

## Что должен делать каждый раздел

1. **Сужать выбор.** Раздел — это ограничение: по нему можно отбраковать вариант.
   «Мрачно и тревожно» не исключает ничего. «Один тёплый источник на комнату, остальное —
   холодные лампы дневного света, тени жёсткие» — исключает.
2. **Ссылаться на столп.** Каждый принцип называет столп опыта (раздел 0), которому служит.
   Принцип, который не нужен ни одному столпу, — вкус. Он вычёркивается.
3. **Давать проверку.** «Если сомневаешься в X, выбирай Y». Не получается написать проверку —
   принцип слишком расплывчатый.
4. **Не спорить с утверждёнными разделами.** Цвет служит настроению мест, персонажи читаются на
   фоне плотности предметов, интерфейс либо повторяет мир, либо намеренно отличается — и сказано,
   что именно.
5. **Опираться на мир.** Свет — от источника в мире, износ — от истории предмета, кадр — от
   того, кто и зачем снимал.

## Проверки детективной игры (наши)

6. **Улика не красивее фона.** Уровень детали одинаков у важного и неважного, иначе игрок ищет
   по качеству картинки, а не по смыслу (P-1: игра не думает за игрока).
7. **Читаемость при внимательном взгляде.** Деталь, нужная для вывода, различима при увеличении
   на обычном экране; без увеличения — не обязана.
8. **Нет лишней подсказки.** Ни одна примета, цвет или ракурс не указывает на виновного сам по
   себе, если этого нет в каноне.
9. **Канон не меняется.** Арт-библия описывает, как выглядит то, что уже решено в сводах
   `bunker/01–04`. Если визуальной задаче нужно изменение канона — это вопрос автору через
   `detective-orchestrator`, а не строка в арт-библии.
10. **Происхождение.** У каждого типа изображения есть автор в мире, время, носитель и причина
    существования.
11. **Одна эпоха.** Техника, одежда, шрифты, интерфейсы — осень 2009 (мир дела) или эпоха мира
    следователя (раздел 2).

## Проверки по разделам

| Раздел | Готов, когда |
|---|---|
| 0. Столпы | 3–5, ранжированы, у каждого пример момента в игре |
| 1. Идентичность | одна строка + 2–3 принципа, у каждого проверка и столп |
| 2. Два мира | по кадру без подписи ясно, к какому миру он относится |
| 3. Места | у каждого места: эмоция, свет с источником, определения, несущий элемент; места не путаются на миниатюре |
| 4. Носители | профиль на каждый носитель из каталога материалов; профили различимы |
| 5. Цвет | 5–7 цветов на мир, роли; опасные для дальтоников пары названы и подстрахованы |
| 6. Персонажи | лист на каждого; узнаётся на трёх носителях; приметы не подсказывают виновного |
| 7. Места и пространство | геометрия из 3D-блокаута; точка обзора каждого кадра есть на плане |
| 8. Бумага | у каждого следа есть причина; реальные образцы бланков названы |
| 9. Видео | время и порядок по таймлайну; таймкод программный |
| 10. Звук | голоса узнаются по опоре; важный звук слышен на обычных наушниках |
| 11. Интерфейс | важное заметно, улики не подсвечены |
| 12. Запреты | каждый запрет проверяется глазом |
| 13. Стандарты | по имени файла и карточке ясно, чем и зачем сделан файл |
| 14. Референсы | у каждого конкретное «берём» и «избегаем»; два не дублируют друг друга |

## Границы

- Не переписывать столпы. Если столп мешает визуальной цели — показать автору как компромисс.
- Не решать сюжет, улики и доступы — это своды и detective-skills.
- Не добавлять объём (новые медиа, новые материалы) — только описывать вид существующих.

## Итоговая проверка перед «Утверждена»

Первой строкой — вердикт: `ГОТОВО` / `ЗАМЕЧАНИЯ: <разделы>` / `НЕ ГОТОВО: <противоречия>`.
Дальше — причины, у каждой номер раздела. Раздел, которого в арт-библии нет, хотя он нужен
(например, нет палитры мира следователя), — это замечание, а не «не проверено».
