# БУНКЕР — разработка: установка, запуск, переезд

Рабочий документ для автора и для Claude. Обновляется после каждой законченной части
работы (правило `game/CLAUDE.md`). Решения, на которых он стоит, — ST-1…ST-6 в
`DECISIONS.md`.

## 1. Установка на компьютер автора (один раз)

Шаги 1–6 делает автор: установщикам нужны права администратора и клики в окнах.
Всё остальное (раздел 2) делает Claude в VS Code.

**0. Проверить.** Windows 10/11 (64-бит) или macOS; свободно ~20 ГБ; права
администратора; claude.ai открывается на этом компьютере (расширение входит тем же
аккаунтом).

**1. Git** — система версий, через неё код уходит в GitHub.
- Windows: https://git-scm.com → Download for Windows → установщик, все пункты по
  умолчанию (в комплекте — Git Credential Manager для входа в GitHub).
- macOS: в Терминале `xcode-select --install` (git входит в набор).

**2. Node.js** — среда, в которой работают игра и сервер.
- https://nodejs.org → версия **LTS** → установщик, пункты по умолчанию.
- Начиная с Node.js 25 в установщик не входит corepack, поэтому pnpm ставится
  отдельно: `npm install -g pnpm` (делает Claude).

**3. VS Code** — редактор, в котором работает Claude.
- https://code.visualstudio.com → установщик. В Windows отметить «Добавить в PATH» и
  «Открыть с помощью Code» в контекстном меню.

**4. Docker Desktop — локально не обязателен (решение автора 06.11).** На компьютере
автора Docker не встал (Windows: ошибка 23 «CRC» при включении компонента
VirtualMachinePlatform). Локально база — настоящий PostgreSQL, который Claude ставит
пакетом npm прямо в проект (без установщика); Docker используется только на сервере.
Одинаковость «локально = сервер» проверяется на пробном переезде. Если позже Docker
понадобится — шаги ниже.

Docker Desktop (для справки) — запускает базу данных и сервер в «контейнерах», так же,
как на сервере.
- https://www.docker.com/products/docker-desktop → установщик. В Windows он попросит
  включить WSL 2 — согласиться, перезагрузить компьютер.
- Бесплатен для личного использования и небольших компаний.
- **Если сайт или загрузка образов не работает из России** (Docker Hub с 2024 года
  то блокировал пользователей из РФ, то снова открывал) — не страшно: Claude настроит
  зеркало (например, Яндекса) или поставит базу без Docker. Просто сообщите.

**5. Расширение Claude Code.**
- VS Code → значок «Расширения» слева (Ctrl+Shift+X / Cmd+Shift+X) → найти
  **Claude Code** (издатель Anthropic) → Install.
- Открыть панель (значок-искра справа вверху) → **Sign in** → войти в браузере тем же
  аккаунтом Claude.

**6. Репозиторий.**
- VS Code → Ctrl+Shift+P → «Git: Clone» → «Clone from GitHub» → войти в GitHub →
  выбрать `retrocasual-motion/Detective-game-BUNKER` → папка **`E:\Projects`** (у автора;
  путь без пробелов и кириллицы, не в облачной папке) → получится
  `E:\Projects\Detective-game-BUNKER`.
- Медиа — отдельно, вне репозитория: `E:\Projects\bunker-media` (её синхронизировать
  с облаком).
- На вопрос «Доверяете ли вы авторам?» — **Да** (иначе расширение не работает).

**7. Первая команда Claude.** Открыть панель Claude и написать:

> Прочитай `game/README.md` (раздел «Для Claude: начни здесь») и выполни раздел 2
> `game/docs/DEVELOPMENT.md`.

Claude будет спрашивать разрешение на команды — это нормально; разрешать.

**8. Копия медиа.** Завести папку на облачном диске (Яндекс Диск и т. п.) для
голосов, видео, 3D и сканов — до переезда на сервер это единственная копия (ST-5).

## 3. Запуск и проверки

**Проще всего — двойной щелчок:** `ИГРАТЬ.cmd` в корне репозитория (или ярлык
«БУНКЕР — играть» на рабочем столе). Открывается окно сервера: оно ставит недостающие
пакеты (нужно после слияний), запускает игру и само открывает браузер, когда сервер и
база готовы. Игра уже запущена — просто открывает страницу. **Остановить — закрыть окно
сервера.** Ярлык создаётся один раз (PowerShell, `WScript.Shell`; цель — `ИГРАТЬ.cmd`).

Все команды — в папке `game/` (терминал VS Code: «Терминал → Создать терминал», затем
`cd game`). Карта кода — `ARCHITECTURE.md`.

**Первый раз на компьютере:** `pnpm install`, затем
`pnpm --dir packages/game-web exec playwright install chromium` (браузер для автотестов).
Файл `.env` не обязателен: без него берутся значения по умолчанию из `.env.example`.

**Запустить игру:** `pnpm dev` → открыть в браузере **http://localhost:5173**.
Поднимаются три процесса: база (PostgreSQL на порту 5433, данные — `game/.data/pg`,
в git не попадают), сервер (порт 8787) и клиент (Vite, порт 5173; правки кода видны
сразу, без перезапуска). Остановить — `Ctrl+C` в том же терминале
или закрыть окно (база останавливается вместе с остальными; если она всё же осталась
работать, следующий запуск её подхватит, а если осталась зависшей — порт занят, а база не
отвечает, — запуск сам завершит её процессы из папки игры и поднимет базу заново). Раскладка стены хранится в базе и переживает
перезапуск.

**Проверить все важные ходатайства по сценарию** — пошаговый список
`docs/PETITION_CHECKLIST.md` (что вводить, какой ответ должен прийти). В служебной строке —
кнопки «Подготовка к ходатайствам» (команда `ПОДГОТОВКА`: открыть адреса и материалы для
списка) и «Разложить стену по порядку» (команда `ПОРЯДОК`: 01, 02… сеткой, повешенные письма и
записки — ниже; нити остаются).

**Конверты архива (A-260).** Новое дело: на стене персонажи и 01–07, остальное — в конвертах и
коробке на столе (щелчок — вскрыть). Старое сохранение (до конвертов) считается вскрытым
целиком: чтобы увидеть старт с конвертами, введите в служебной строке `СБРОС`. Адрес
`http://localhost:5173/?opened=all` — сразу всё вскрыто (так стартуют автотесты; тесты
конвертов — `test.use({ sealed: true })`).

**Вещь в руках (этап 4a).** Щелчок по конверту, коробке «Личные вещи» или устройству на столе
(и по карточке устройства на стене) — вещь крупно. Зажать и тянуть — вращать без крена (конверт только
переворачивается: лицо или оборот), колесо — ближе к точке под курсором, средняя кнопка — как
было, щелчок мимо, ✕ или Esc — положить. Щелчок по печати (пломбе) — вскрыть; по экрану
ноутбука и телефона — экран к игроку (4c-1, 4c-2), прочих устройств — пока лист материала (4d…). Сцена three.js грузится при первом
взятии вещи.

**Ноутбук (4c-1).** Первый раз — графический ключ (мышью через точки или цифры 1–9 и Enter); потом — «Войти». Лимит ввода — 5 неверных, потом 2 минуты (сервер, `GAME_CONFIG`). Файлы, окна и значки остаются на ноутбуке и сохраняются в `state.laptop`; часы — время игрока, дата 16.11.2009 плюс прошедшие дни (`state.started`).

**Телефон (4c-2).** Первый раз — код (клавиатура на экране или цифры; 0110 / 1001), потом — «slide to unlock». Лимит — как у ноутбука. Что открыто — `state.phone`; файлы — на телефоне.

**Компьютер следователя (4c-3).** Щелчок по монитору на столе — рабочее место бюро крупно (Esc или щелчок мимо — отойти). Значки: «Поступления» (вложения ответов бюро — сами, по мере ответов), «Экспорт сервера VL-31» (терминал; вкладки F1… по мере выгрузок), «Браузер» (архив номеров газеты — поле «Дата выпуска»). Зашифрованные вложения — окно пароля (тоффи; 0417), лимит — как у ноутбука. Окна и значки — `state.pc`; файлы — на компьютере (`DEVICE_MATERIALS.pc`). Проверить руками: служебная строка → «КОМПЬЮТЕР» (или кнопка «Ответы бюро для компьютера») — все ответы бюро для компьютера; пароли и даты вводятся на компьютере. В e2e — тоже служебная строка (`/api/dev/action-line`, `e2e/pc.spec.ts`).

**Блокнот.** Язычок внизу справа; поверх листа, вещи и ноутбука; записи — `state.notebook`. Папка ходатайства тоже лежит поверх ноутбука.

**Лист в руках (этап 4b).** Длинный документ — страницами: за листом стопка (края следующих
страниц справа, прочитанных — слева); щелчок по стопке или по загнутому уголку — страница (или
←/→). Лист не переворачивается: он «живой» — край под мышью чуть приподнимается, по бумаге
скользит блик. Колесо — ближе к точке под курсором; глубоко — записка
«крупный план» от движка (открытое — во «Входящие»). Средняя кнопка — как было.

**Время чтения (RD-A)** — в служебной строке кнопка «Время чтения»: сколько секунд каждый
материал был открыт (считается, пока вкладка видна и вы что-то делали за последнюю минуту) и
сколько раз. «Скопировать таблицу» — для вставки в чат или таблицу; «Сбросить» — перед новым
прогоном. Хранится в браузере, только в режиме разработки.

**Проверить ходатайство (этап 3) — как игрок:** уголок «Ходатайство» внизу слева → щёлкнуть
«Кому» → адрес из книги; открыть лист со стены, щёлкнуть по строке (или протянуть
мышью по словам) → «В ходатайство» (или перетащить лист в поле); «Отправить» → штамп. Ответ ложится письмом в лоток «Входящие» на
столе через `MAIL_DELAY_MS` (по умолчанию 12 с; в автотестах — 1,5 с). Пример, который
даёт ответ по существу: Кому `zapros@okrug-bureau.org`, Прошу — из 25 «ключ плоский
металлический, штамп DO NOT DUPLICATE, номер 845», На основании — из 45 «Бумажник».

**Проверить движок правил руками (этап 2):** вверху слева — язычок «Служебная строка»
(только в режиме разработки, игрокам не виден). Действие пишется как в сквозном проходе пакета
(`gm/walkthrough.txt`): `ДЕЙСТВИЕ | ЦЕЛЬ | ЗНАЧЕНИЕ` — строку можно копировать из прохода
целиком, хвост «=> ожидание» и «# комментарий» отрезается сам. Например
`ОСМОТР | 29 | листать П-01` или
`ХОДАТАЙСТВО | zapros@okrug-bureau.org | прошу: 04, «строка» ; основание: 06, «строка»`.
Ответ правила появляется под строкой, открытый материал встаёт письмом в лоток «Входящие»
на столе (щелчок — прочитать, «На стену» — повесить). Звонков в строке нет (телефонные линии — этап 6). **Начать дело заново** — ввести
в строку `СБРОС` (сбрасывает прогресс и раскладку стены; только в разработке).
Осторожно: `РЕШИТЬ | дело | продолжить`, ФИНАЛ и СТОП закрывают расследование (P-9) —
дальше только `СБРОС`.

**Проверки (то же, что CI на каждом PR):**

| Команда | Что проверяет |
|---|---|
| `pnpm typecheck` | типы TypeScript во всех пакетах |
| `pnpm lint` | линтер и форматирование (Biome); `pnpm format` — исправить форматирование |
| `pnpm test` | модульные тесты (Vitest): сборка контента, состояние, сервер на настоящей базе, движок правил — в том числе все сквозные проходы пакета (`gm/walkthrough*.txt`) |
| `pnpm e2e` | клики в браузере (Playwright, экран 1366×768, без анимаций — фикстура включает игровую настройку «уменьшить движение» (RM-A), когда `reducedMotion: 'reduce'`; движение проверяют тесты с `'no-preference'`; лист под открытой папкой ходатайства — `bringIntoView` в `e2e/fixtures.ts` двигает доску); своя база и порты (5434, 8788, 5174) — раскладку в `game/.data/pg` не трогает |

CI (`.github/workflows/game.yml`) дополнительно собирает Docker-образ и проверяет, что
игра в нём отвечает так же, как на сервере, и что пакета игрока в образе нет.

**Если что-то не запускается:**
- `pnpm : Невозможно загрузить файл …\pnpm.ps1 … выполнение сценариев отключено` —
  Windows по умолчанию запрещает PowerShell запускать скрипты. Один раз выполнить
  `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned` (только для своей учётной записи,
  прав администратора не нужно) и открыть новый терминал. Без изменения настройки —
  писать `pnpm.cmd` вместо `pnpm`;
- «порт занят» (5173 или 8787) — не закрыт прошлый `pnpm dev`: закрыть его окно или
  терминал, или перезагрузить окно VS Code. Занятый порт базы (5433) не мешает: запуск
  подхватывает уже работающую базу, а зависшую (случай 09.11: умер главный процесс, а его
  служебный `postgres.exe` держит порт) убирает сам. Чужую программу на порту не трогает —
  пишет, что делать;
- база не стартует после аварийного завершения — в `game/` выполнить

## 5. Переезд на сервер (после первой сборки, ST-5)

Шаги уточняются по мере работы; основа — требования ST-6:

1. Арендовать VPS Timeweb Cloud (Россия), поставить Docker.
2. Записи DNS для `artemwork-work.ru`: поддомены игры и сайтов; SPF/DKIM для почты.
3. Создать хранилище S3; выгрузить медиа скриптом по манифесту; проверить «чего не
   хватает».
4. Заполнить `.env` сервера: адреса, хранилище, ключи почты, режимы каналов.
5. Запустить тот же Docker Compose; миграции базы; сборка контента.
6. Проверить: вход по ссылке, письмо и «Добавить в дело» с телефона, сайты по
   поддоменам, снимки страниц, тесты Playwright против сервера.
7. Ежедневная копия базы.
