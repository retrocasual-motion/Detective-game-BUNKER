## 3D рисуется по требованию (CI-B) — автор, 18.11.2026

Сцена «вещь в руках» (`Held3D`) рисуется не 60 раз в секунду всегда, а только когда что-то
меняется (`frameloop="demand"`). Варианты: CI-A — только убрать лишнюю раскладку живого экрана
(сделано, но CI не позеленел); CI-B — рисовать по требованию (выбрано); CI-C — дать 3D-тестам
больше времени в CI (обход); T-A…T-D — тестировать на компьютере автора, свой runner, платный
GitHub с видеокартой (не выбраны). Почему: Chrome автотестов рисует 3D процессором (SwiftShader;
так и локально, но у автора процессор быстрее), и на слабой машине CI постоянная перерисовка
не оставляла времени тестам (14 падений); у игроков та же постоянная
перерисовка грела бы ноутбук и садила батарею, пока вещь в руках (совпадает с находкой R3-03
разбора 18.11).

| Решение Claude | Почему | Как откатить |
|---|---|---|
| Плавные движения частей — `useAnimate` (`hold/animate.ts`): просит следующий кадр, пока не доехало (разница > 1e-4); после каждой отрисовки компонента — один кадр | иначе анимация останавливалась бы на первом кадре | `useFrame` вместо `useAnimate` |
| Любой ввод в окне (указатель, колесо, клавиши) — кадр; захват до `stopPropagation` разметки | жесты копятся в `gesture` и забираются кадром | `Rig` в `Held3D.tsx` |
| Первый кадр после простоя — с dt не больше 1/30 с | иначе движение перескакивало бы к цели за один кадр | `MAX_DT` |
| Новая кнопка части и живой экран — сразу кадр | им место ставит кадр сцены | `changed`, `useScreenAnchor` |
| При «уменьшить движение» лист пачки переворачивается без полёта | без полёта щелчок сразу после смены номера не попадает в переворот (на обложке он пропадал; автотест П-09) | `Papers`, эффект по `page` |
