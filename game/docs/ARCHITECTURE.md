## Пакеты (`game/packages/`, pnpm workspaces)

| Пакет | Что делает | Главные файлы |
|---|---|---|
| `shared` | общие типы и правила состояния для сервера и клиента | `schemas.ts` — Zod-схемы `Material`, `PlayerState` (вид, стол, доска); `layout.ts` — `defaultState` (россыпь: ряды со сдвигом, разброс и поворот по номеру места — одинаково у всех), `upgradeState` (сохранение старой версии → текущая) и `reconcile` (привести сохранённое к текущему контенту) |
| `content` | сборка контента из пакета игрока | `build.ts` — `playtest/packs/v3.3-…/player/NN__*.md` → `Material[]`; устройства `24, 47–50` → `placement: 'evidence'`; `cli.ts` → `dist/starting.json` |
| `api` | сервер: Hono + PostgreSQL (Drizzle) | `app.ts` — маршруты; `db/schema.ts` — таблица `player_state`; `server.ts` — запуск, отдача клиента в production; `startup.ts` — ожидание базы и миграции с повтором (причина ошибки — в лог); `env.ts` — настройки из `game/.env`; `scripts/dev-db.ts` — встроенный PostgreSQL для разработки |
| `game-web` | клиент: React + Vite + Zustand | см. ниже |
| (этап 2) `engine` | движок правил на `access.json` | — |

## Поток данных

```
пакет игрока (md) ──content build──▶ starting.json ──api──▶ GET /api/materials ──▶ клиент
                                                           GET/PUT /api/state  ◀─▶ клиент (раскладка)
                                                           PostgreSQL: player_state (jsonb)
```

- **Материалы** приходят в браузер только стартовые (P-10). Закрытые и правила появятся
  на сервере на этапе 2 и в браузер до открытия не попадают.
- **Состояние игрока** — один JSON (`PlayerState`, версия `STATE_VERSION` = 3): текущий вид,
  камера и бумаги стола (место, поворот, порядок), камера, копии и нити доски. Сервер при
  чтении поднимает старую версию (`upgradeState`: версии 1 и 2 — стол заново россыпью,
  доска и вид остаются). Сервер проверяет схему и то, что все материалы известны
  и лежат на своих местах (устройство на столе → 400). При чтении `reconcile` убирает
  то, чего больше нет в контенте, и докладывает новое.
- **Игрок пока один** (`player_id = 'local'`); вход и аккаунты — этап 6.

## API

| Маршрут | Ответ |
|---|---|
| `GET /api/health` | `200 {"ok":true}`; `503 {"ok":false}`, пока миграции не применены |
| `GET /api/materials` | стартовые материалы (все `/api/*`, кроме health, отвечают 503, пока база не готова; клиент повторяет раз в секунду) |
| `GET /api/state` | состояние игрока (или по умолчанию) |
| `PUT /api/state` | `204`; неверная схема или чужой материал — `400`. Заголовок `x-state-seq` — номер версии: запрос старее уже сохранённого не применяется (старый ответ, пришедший позже, не затирает новый) |
| `DELETE /api/state` | сброс (только не в production) — для автотестов |

В production (`WEB_DIST` задан) тот же сервер отдаёт собранный клиент; любой путь,
кроме `/api/*`, — `index.html`.

## Клиент (`game-web/src/`)

| Файл / папка | Что |
|---|---|
| `store.ts` | Zustand: материалы, состояние, статус сохранения, открытый материал; `updateState` — любое изменение + отложенное сохранение |
| `save.ts` | `createSaver`: сохраняет через 500 мс после последнего изменения, только последнее состояние, с растущим номером версии; при закрытии страницы — сразу; после ошибки — «Не сохранено» и повтор через 3 с |
| `room/` | **серая 3D-комната** (ROOM-B). `RoomScene` — все три вида смонтированы как грани комнаты (CSS 3D), переход — камера кадрами из JS, в покое активный вид лежит плоско (без 3D: чёткий текст, честные координаты мыши); в общем виде грани — зоны для щелчка. `camera.ts` — позы камеры, грани, проекция (проверена тестом против матриц CSS); `decor.ts` — стены, пол, окно, подставка стола на `<canvas>` своей проекцией (большие CSS-плоскости браузер рисует с дырами); `NavArrows` — стрелки вплотную к краям, с подписями, значок по движению камеры (UX-F); `views.ts` — куда ведёт каждая стрелка. Переход: в общий вид и из него — 650 мс, между рабочими видами — 400 мс (`transitionMs`, MOVE-A); стрелки видны и во время перехода, щелчок ведёт к новой цели с места |
| `canvas/` | `Canvas` — поверхность (фон тянется, колесо масштабирует 0.25…3); у стола — край (`bounds` + `surface`, `clampToBounds`: центр экрана не уходит со столешницы, отдалить — до всего стола); `useDraggable` — перетаскивание объектов (живое смещение `onMove`, наклон `tilt`); `math.ts` — экран ↔ мир |
| `desk/` | стол (DESK-A, UX-A1): материал лежит предметом своего типа (`Material.kind` из сборки контента: лист, скреплённые листы, половина листа, фото, пачка, тетрадь, диск в конверте, пакет вещдоков; формы — `app.css`, `.paper-<kind>`), с поворотом и тенью; столешница `DESK_BOUNDS` (`shared/layout.ts`); взятый — поверх, приподнят, наклон по скорости руки, после отпускания оседает; один клик или Enter — открыть |
| `viewer/` | просмотрщик: текст пакета дословно; строки внутри абзаца склеены (`text.ts`, `unwrapLines`: строка с маленькой буквы — продолжение), колонка ~66 знаков (UX-C1); инструменты идут за курсором по высоте, пока он над листом (UX-D1); затемнение 30 % (UX-E1); закрыть — щелчок мимо листа (не в первые 0,4 с), ✕ у угла листа, Esc; при открытой папке лист сдвигается вправо |
| `board/` | доска (TH-B): нить тянется от булавки к другой копии — или двумя щелчками: булавка, затем копия; мимо или Esc — отмена (UX-J1); щелчок по копии — открыть; ✕ — снять; щелчок по нити — подпись, двойной — удалить (по подписи — правка); «Вернуть» 5 с; нити идут за копией во время перетаскивания. `board-actions.ts` — чистые функции (в т. ч. `takeFromBoard`/`restoreToBoard`) |
| `left/` | компьютер следователя (разделы пока пустые) и полка изъятых устройств |
| `petition/` | папка ходатайства (PET-A): уголок внизу слева, открытая — слева на треть экрана, без затемнения; поля — места под карточки (наполнение — этап 3) |
| `theme/tokens.css` | **шкура**: все цвета, шрифты, размеры. Этап дизайна меняет этот файл, а не компоненты |

## Где что менять

- Новое поле состояния игрока → `shared/schemas.ts` (+ `defaultState`, `reconcile`); если старое сохранение без него не читается — поднять `STATE_VERSION` и научить `upgradeState`; тесты в `shared`.
- Комната: позы камеры, длительность перехода → `room/camera.ts`; стены, пол, окно → `room/decor.ts`; куда ведут стрелки → `room/views.ts`.
- Новый маршрут → `api/src/app.ts`, тест в `api/test/`.
- Новая таблица → `api/src/db/schema.ts`, затем `pnpm -F @bunker/api db:generate` (миграция в `api/drizzle/`).
- Внешний вид → только `theme/tokens.css` и `app.css`.
- Какие материалы — устройства → `content/src/build.ts` (`EVIDENCE_IDS`).
