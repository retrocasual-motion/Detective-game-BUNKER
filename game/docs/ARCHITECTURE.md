## Пакеты (`game/packages/`, pnpm workspaces)

| Пакет | Что делает | Главные файлы |
|---|---|---|
| `shared` | общие типы и правила состояния для сервера и клиента | `schemas.ts` — Zod-схемы `Material`, `PlayerState` (вид, стол, доска); `layout.ts` — `defaultState` (россыпь: ряды со сдвигом, разброс и поворот по номеру места — одинаково у всех), `upgradeState` (сохранение старой версии → текущая) и `reconcile` (привести сохранённое к текущему контенту) |
| `content` | сборка контента из пакета игрока | `build.ts` — `playtest/packs/v3.3-…/player/NN__*.md` → `Material[]`; устройства `24, 47–50` → `placement: 'evidence'`; форма на столе — `kind`; закрытые `locked/L…` и правила `gm/access.json` → `buildServerContent`; `cli.ts` → `dist/starting.json` (клиенту) и `dist/server.json` (только серверу, P-10) |
| `api` | сервер: Hono + PostgreSQL (Drizzle) | `app.ts` — маршруты, действия через движок (по очереди на игрока); `db/schema.ts` — таблицы `player_state` (раскладка, пишет клиент) и `player_progress` (прогресс дела, пишет только сервер); `server.ts` — запуск, отдача клиента в production; `startup.ts` — ожидание базы и миграции с повтором (причина ошибки — в лог); `env.ts` — настройки из `game/.env`; `scripts/dev-db.ts` — встроенный PostgreSQL для разработки |
| `game-web` | клиент: React + Vite + Zustand | см. ниже |
| `engine` | движок правил на `access.json` (TECH_PLAN 6.1–6.2), чистые функции без базы | `engine.ts` — `act` (одно действие → ответ правила, открытые материалы, новый прогресс): `resolve`, `resolvePetition` (карточки, `not_cards`, `early`), форма заключения (P-9), лимиты попыток по времени (T-11-A, пауза 10 мин); `pyre.ts` — перевод шаблонов Python `re` в JS (`\b`, `\w`, `\W` по Unicode); `text.ts` — `norm`, `qnorm`, `findQuote` (как в прототипе); `walk.ts` — сквозной проход и разбор строки «ДЕЙСТВИЕ \| ЦЕЛЬ \| ЗНАЧЕНИЕ»; `pack.ts` — чтение пакета с диска (тесты); `walk.test.ts` — walkthrough*.txt пакета как автотесты |

## Поток данных

```
пакет игрока (md) ──content build──▶ starting.json ──api──▶ GET /api/materials ──▶ клиент
                 └──────────────────▶ server.json (правила + закрытые) ─▶ engine (только сервер)
клиент ── POST /api/action ──▶ api ──▶ engine.act ──▶ player_progress ──▶ ответ + открытые материалы
                                                           GET/PUT /api/state  ◀─▶ клиент (раскладка)
                                                           PostgreSQL: player_state, player_progress
```

- **Материалы.** В браузер приходят стартовые и те закрытые, которые этот игрок открыл (P-10).
  Правила, тексты закрытых и правильные ответы — только в `server.json` на сервере.
- **Прогресс дела** (`Progress` движка: открытое, «видено», неверные попытки, почта
  специалиста, конец дела) — таблица `player_progress`; пишет только сервер. Клиент не может
  положить на стол неоткрытый материал (PUT → 400). «Видено» отмечается, когда клиент
  забрал материалы (`GET /api/materials`) — от этого зависит форма заключения.
- **Состояние игрока** — один JSON (`PlayerState`, версия `STATE_VERSION` = 3): текущий вид,
  камера и бумаги стола (место, поворот, порядок), камера, копии и нити доски. Сервер при
  чтении поднимает старую версию (`upgradeState`: версии 1 и 2 — стол заново россыпью,
  доска и вид остаются). Сервер проверяет схему и то, что все материалы известны
  и лежат на своих местах (устройство на столе → 400). При чтении `reconcile` убирает
  то, чего больше нет в контенте, и докладывает новое.
- **Игрок пока один** (`player_id = 'local'`); вход и аккаунты — этап 6.

## API

| Маршрут | Ответ |
|---|---|
| `GET /api/health` | `200 {"ok":true}`; `503 {"ok":false}`, пока миграции не применены |
| `GET /api/materials` | стартовые материалы + открытые этим игроком (все `/api/*`, кроме health, отвечают 503, пока база не готова; клиент повторяет раз в секунду) |
| `POST /api/action` | `{action, target, value?, cards?}` → `{result, reply, released}`: ответ правила и открытые материалы. ЗВОНОК — нет (телефонные линии — этап 6) |
| `POST /api/dev/action-line` | только не в production (E2-CHECK-A): `{line: "ДЕЙСТВИЕ \| ЦЕЛЬ \| ЗНАЧЕНИЕ"}` → тот же движок |
| `GET /api/state` | состояние игрока (или по умолчанию) |
| `PUT /api/state` | `204`; неверная схема или чужой материал — `400`. Заголовок `x-state-seq` — номер версии: запрос старее уже сохранённого не применяется (старый ответ, пришедший позже, не затирает новый) |
| `DELETE /api/state` | сброс раскладки и прогресса (только не в production) — для автотестов |

В production (`WEB_DIST` задан) тот же сервер отдаёт собранный клиент; любой путь,
кроме `/api/*`, — `index.html`.

## Клиент (`game-web/src/`)

| Файл / папка | Что |
|---|---|
| `store.ts` | Zustand: материалы, состояние, статус сохранения, открытый материал; `updateState` — любое изменение + отложенное сохранение |
| `save.ts` | `createSaver`: сохраняет через 500 мс после последнего изменения, только последнее состояние, с растущим номером версии; при закрытии страницы — сразу; после ошибки — «Не сохранено» и повтор через 3 с |
| `room/` | **серая 3D-комната** (ROOM-B). `RoomScene` — все три вида смонтированы как грани комнаты (CSS 3D), переход — камера кадрами из JS, в покое активный вид лежит плоско (без 3D: чёткий текст, честные координаты мыши); в общем виде грани — зоны для щелчка. `camera.ts` — позы камеры, грани, проекция (проверена тестом против матриц CSS); `decor.ts` — стены, пол, окно, подставка стола на `<canvas>` своей проекцией (большие CSS-плоскости браузер рисует с дырами); `NavArrows` — стрелки вплотную к краям, с подписями, значок по движению камеры (UX-F); второй щелчок двойного по стрелке не считается; `views.ts` — куда ведёт каждая стрелка. Переход: в общий вид и из него — 650 мс, между рабочими видами — 400 мс (`transitionMs`, MOVE-A); стрелки видны и во время перехода, щелчок ведёт к новой цели с места |
| `canvas/` | `Canvas` — поверхность (фон тянется, колесо масштабирует 0.25…3); у стола — край (`bounds` + `surface`, `clampToBounds`: центр экрана не уходит со столешницы, отдалить — до всего стола; у предела колесо не двигает стол; поправка при загрузке и смене размера окна); `useDraggable` — перетаскивание объектов (живое смещение `onMove`, наклон `tilt`); `math.ts` — экран ↔ мир |
| `desk/` | стол (DESK-A, UX-A1): материал лежит предметом своего типа (`Material.kind` из сборки контента: лист, скреплённые листы, половина листа, фото, пачка, тетрадь, диск в конверте, пакет вещдоков; формы — `app.css`, `.paper-<kind>`), с поворотом и тенью; столешница `DESK_BOUNDS` (`shared/layout.ts`), лист за край не уронить; взятый — поверх, приподнят, наклон по скорости руки, после отпускания оседает; один клик или Enter — открыть |
| `viewer/` | просмотрщик: текст пакета дословно; строки внутри абзаца склеены (`text.ts`, `unwrapLines`: длинная строка + следующая с маленькой буквы, не пункт «п.1.»; тест на всём пакете — слова не теряются), колонка ~66 знаков (UX-C1); Markdown разбирается один раз на материал; закрыть — щелчок мимо листа (не в первые 0,4 с), ✕ у края листа, Esc; инструменты (✕, «Прикрепить к доске») идут за курсором по высоте, пока он над листом (UX-D1); затемнение 30 % (UX-E1); при открытой папке лист сдвигается вправо |
| `board/` | доска (TH-B): нить тянется от булавки к другой копии — или двумя щелчками: булавка, затем копия; щелчок мимо на доске, правой кнопкой, вне доски (стрелка, папка) или Esc — отмена; режим сам кончается при уходе с доски и открытии листа (UX-J1); щелчок по копии — открыть; ✕ — снять; щелчок по нити — подпись, двойной — удалить (по подписи — правка); «Вернуть» 5 с; нити идут за копией во время перетаскивания. `board-actions.ts` — чистые функции (в т. ч. `takeFromBoard`/`restoreToBoard`) |
| `left/` | стол вещдоков (LEFT-B): монитор компьютера следователя со значками разделов (окно с «Пусто» — разделы наполнят этапы 3, 4, 6) и изъятые устройства — серые силуэты с бирками «Изъято»; щелчок по устройству пока открывает описание (включение и замки — этап 4) |
| `desk/InboxTray.tsx` | лоток «Входящие» (E2-INBOX-A): внизу справа, зеркально папке; открытое по ходу дела лежит стопкой, свежее сверху; щелчок — открыть, утащить на стол или «На стол» — вынуть; записка «Добавлено в дело» над лотком |

## Где что менять

- Новое поле состояния игрока → `shared/schemas.ts` (+ `defaultState`, `reconcile`); если старое сохранение без него не читается — поднять `STATE_VERSION` и научить `upgradeState`; тесты в `shared`.
- Комната: позы камеры, длительность перехода → `room/camera.ts`; стены, пол, окно → `room/decor.ts`; куда ведут стрелки → `room/views.ts`.
- Новый маршрут → `api/src/app.ts`, тест в `api/test/`.
- Новая таблица → `api/src/db/schema.ts`, затем `pnpm -F @bunker/api db:generate` (миграция в `api/drizzle/`).
- Внешний вид → только `theme/tokens.css` и `app.css`.
- Какие материалы — устройства → `content/src/build.ts` (`EVIDENCE_IDS`); форма на столе — `KIND_BY_ID`, `lockedKind`.
- Правила дела меняются в пакете (`gm/access.json`, собирает `gm/build_access.py`), не в коде; после правки — `pnpm content:build` и `pnpm -F @bunker/engine test` (сквозные проходы).
- Новое действие движка → `engine/src/engine.ts` (`act`) и схема `ActionSchema` в `api/src/app.ts`.
