# БУНКЕР — карта кода

Для того, кто продолжает разработку. Обновляется после каждой законченной части
(правило `game/CLAUDE.md`). Как запустить и проверить — `DEVELOPMENT.md`, раздел 3.
Состояние на 07.11.2026: M0, этап 1 «Комната и стол» (план —
`planning-archive/2026-11-07-m0-plan/stage1-plan.md`).

## Пакеты (`game/packages/`, pnpm workspaces)

| Пакет | Что делает | Главные файлы |
|---|---|---|
| `shared` | общие типы и правила состояния для сервера и клиента | `schemas.ts` — Zod-схемы `Material`, `PlayerState` (вид, стол, доска); `layout.ts` — `defaultState` (сетка 10 колонок) и `reconcile` (привести сохранённое к текущему контенту) |
| `content` | сборка контента из пакета игрока | `build.ts` — `playtest/packs/v3.3-…/player/NN__*.md` → `Material[]`; устройства `24, 47–50` → `placement: 'evidence'`; `cli.ts` → `dist/starting.json` |
| `api` | сервер: Hono + PostgreSQL (Drizzle) | `app.ts` — маршруты; `db/schema.ts` — таблица `player_state`; `server.ts` — запуск, миграции с повтором, отдача клиента в production; `env.ts` — настройки из `game/.env`; `scripts/dev-db.ts` — встроенный PostgreSQL для разработки |
| `game-web` | клиент: React + Vite + Zustand | см. ниже |
| (этап 2) `engine` | движок правил на `access.json` | — |

## Поток данных

```
пакет игрока (md) ──content build──▶ starting.json ──api──▶ GET /api/materials ──▶ клиент
                                                           GET/PUT /api/state  ◀─▶ клиент (раскладка)
                                                           PostgreSQL: player_state (jsonb)
```

- **Материалы** приходят в браузер только стартовые (P-10). Закрытые и правила появятся
  на сервере на этапе 2 и в браузер до открытия не попадают.
- **Состояние игрока** — один JSON (`PlayerState`): текущий вид, камера и карточки стола,
  камера, копии и нити доски. Сервер проверяет схему и то, что все материалы известны
  и лежат на своих местах (устройство на столе → 400). При чтении `reconcile` убирает
  то, чего больше нет в контенте, и докладывает новое.
- **Игрок пока один** (`player_id = 'local'`); вход и аккаунты — этап 6.

## API

| Маршрут | Ответ |
|---|---|
| `GET /api/health` | `200 {"ok":true}`; `503 {"ok":false}`, пока миграции не применены |
| `GET /api/materials` | стартовые материалы |
| `GET /api/state` | состояние игрока (или по умолчанию) |
| `PUT /api/state` | `204`; неверная схема или чужой материал — `400` |
| `DELETE /api/state` | сброс (только не в production) — для автотестов |

В production (`WEB_DIST` задан) тот же сервер отдаёт собранный клиент; любой путь,
кроме `/api/*`, — `index.html`.

## Клиент (`game-web/src/`)

| Файл / папка | Что |
|---|---|
| `store.ts` | Zustand: материалы, состояние, статус сохранения, открытый материал; `updateState` — любое изменение + отложенное сохранение |
| `save.ts` | `createSaver`: сохраняет через 500 мс после последнего изменения, только последнее состояние, не больше одного запроса одновременно; при закрытии страницы — сразу |
| `room/` | вкладки видов «Комната / Слева / Стол / Справа», стрелки ← →, общий вид зонами |
| `canvas/` | `Canvas` — бесконечная поверхность (фон тянется, колесо масштабирует 0.25…3); `useDraggable` — перетаскивание объектов; `math.ts` — экран ↔ мир |
| `desk/` | стол: карточки материалов, взятая ложится поверх, двойной клик или Enter — открыть |
| `viewer/` | просмотрщик на весь экран: текст пакета дословно (Markdown, переносы строк как в файле) |
| `board/` | доска: копии, нити от булавки к булавке поверх копий, подписи; `board-actions.ts` — чистые функции изменения доски |
| `left/` | компьютер следователя (разделы пока пустые) и полка изъятых устройств |
| `petition/` | уголок папки ходатайства (наполнение — этап 3) |
| `theme/tokens.css` | **шкура**: все цвета, шрифты, размеры. Этап дизайна меняет этот файл, а не компоненты |

## Где что менять

- Новое поле состояния игрока → `shared/schemas.ts` (+ `defaultState`, `reconcile`), тесты в `shared`.
- Новый маршрут → `api/src/app.ts`, тест в `api/test/`.
- Новая таблица → `api/src/db/schema.ts`, затем `pnpm -F @bunker/api db:generate` (миграция в `api/drizzle/`).
- Внешний вид → только `theme/tokens.css` и `app.css`.
- Какие материалы — устройства → `content/src/build.ts` (`EVIDENCE_IDS`).
